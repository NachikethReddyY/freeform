# Feature provenance

This records source lineage for FreeForm features and ideas. Current implementation files belong to FreeForm; no sibling application source files or shape registries have been copied into them.

| FreeForm area | Source / donor | What FreeForm reused or adapted | Verification / boundary |
| --- | --- | --- | --- |
| Multiplayer room, local Durable Object persistence, asset upload plumbing | Existing `freeform/` multiplayer template files: `client/pages/Room.tsx`, `client/multiplayerAssetStore.tsx`, `worker/TldrawDurableObject.ts`, `worker/assetUploads.ts`, and `wrangler.toml` | Kept the room/sync/asset architecture as the base; pinned the tldraw family to 5.4.2, gave the Worker a local identity, and documented the emulator state and cache behavior. | Host dev-server restart preserved the test room and 16×16 PNG. An isolated Compose room on loopback `:5175` retained two shapes and the uploaded PNG across `docker compose restart`; state was mounted from `.wrangler/docker-restart-smoke`, separate from host state. No public routes or deployment were added. |
| Excalifont | npm package `excalifont@1.0.0` | Installed the requested font package and wired it into the editor theme/stylesheet. | Excalifont text is visible in the local browser room after a reload; production build passes. |
| Bounded diagram proposals and MCP | New FreeForm implementation in `shared/diagram.ts`, `worker/diagramProposals.ts`, `worker/TldrawDurableObject.ts`, `client/features/diagrams/*`, and `mcp/*`; concept reference: `../wagent/` | Used the agent donor's broad ideas around board context and explicit review. Implemented a bounded validated diagram contract and local MCP tools; proposals remain outside the synced room until a browser claims them. No `wagent/` source or model/provider integration was copied. | Eleven focused diagram tests and 10 MCP smoke checks pass; no model calls. Browser verification confirmed Mermaid import adds editable native shapes and a locally proposed diagram remains queued until accepted, then adds two nodes and an arrow binding and clears from the queue. Retry/dismiss browser controls and model/provider integration remain unchecked. |
| Frame presentation | New FreeForm implementation in `client/features/presentation/`; concept reference: tldraw native frame shapes | Uses tldraw top-level frames as slides, with deterministic spatial reading order, camera fit/restore, keyboard navigation, optional browser fullscreen, and disposal cleanup. | Seven focused tests cover ordering, navigation, camera/selection/document preservation, keyboard handling, fullscreen support/fallback/exit, and macOS Option key behavior. Browser proof in a synthetic two-frame room confirmed start button and `Alt+Shift+P`, next/previous navigation, browser fullscreen, Escape exit, and restored board controls. |
| Command palette | New FreeForm implementation in `client/features/commandPalette/`; concept reference: `../wworkflow/src/components/OnCanvasComponentPicker.tsx` | The picker concept informed spatial command discovery, but no source was copied or adapted. FreeForm searches native tldraw tools/actions, filters unavailable or read-only-incompatible entries, and executes through the existing registry. | Three focused search/navigation/shortcut tests pass. Integrated browser proof confirmed button and Cmd/Ctrl+K opening, search, Enter selection to run “Zoom to fit”, and visible native shortcut labels. An independent disposable fixture covered 13 commands. |
| FreeForm logo | User-supplied SVG in `public/freeform-logo.svg` | Added the supplied vector as the app favicon. No sibling logo source was reused. | The browser shell displays the supplied FreeForm mark. Favicon behavior has not been independently checked in browser chrome. |
| Visual workflow graphs | `../wworkflow/` and `../wimage/` | Concepts only: typed ports, connected node graphs, template reuse, and execution are useful future ideas. | No code, shape IDs, bindings, or registries have been copied. These remain unchecked in the feature checklist. |
| Chat and agent apps | `../wchat/`, `../wbranch/`, and `../wagent/` | Concepts only beyond the explicitly described proposal/review inspiration above. | No donor chat UI, AI provider route, local storage model, or competing graph schema has been imported. |
| Shader backgrounds and other sibling ideas | `../wshader/`, `../wbasic/` | Reference material only. | No donor code imported; animated backgrounds and broader editing are not part of the current priority. |

The sibling folders are reference material, not runtime dependencies. See [the feature checklist](./FEATURE_CHECKLIST.md) for current scope and incomplete work.
